# מערכת מסחר אוטומטית בקריפטו, זירת Kraken, מצב סימולציה

מערכת שסורקת את זוגות המסחר ב-Kraken, מאתרת קפיצות נפח וזוגות חדשים, מסננת זוגות
לא מתאימים, קובעת גודל פוזיציה לפי סיכון, מבצעת כניסות ויציאות בסימולציה על מחירי
שוק אמיתיים, ומתעדת כל עסקה עם הנימוק לה. לוח המחוונים בעברית, מימין לשמאל.

בגרסה זו המערכת פועלת בסימולציה בלבד. אין בה כסף אמיתי, אין הזמנות אמיתיות,
ואין צורך במפתחות API. מצב המסחר האמיתי חסום בקוד ויתווסף רק בשלב הבא, לאחר
תקופת סימולציה ואישור מפורש.

אזהרה: מסחר בקריפטו כרוך בסיכון להפסד מלא של הכסף. האסטרטגיה כאן בסיסית ומתועדת
לצורך לימוד ובחינה. תוצאות הסימולציה אינן מבטיחות דבר לגבי מסחר אמיתי.

## התקנה והפעלה (ללא ניסיון קודם)

### שלב 1: התקנת Python
1. היכנסו לאתר python.org, לחצו Downloads והורידו את הגרסה העדכנית (3.11 ומעלה).
2. ב-Windows: בחלון ההתקנה סמנו את התיבה "Add Python to PATH" ורק אז לחצו Install.
3. ב-Mac: התקינו את הקובץ שהורד כרגיל.

### שלב 2: הפעלה
1. פתחו את התיקייה crypto-trader.
2. ב-Windows: לחצו לחיצה כפולה על הקובץ start.bat.
   ב-Mac: פתחו Terminal, הקלידו bash ואז גררו את הקובץ start.sh לחלון ולחצו Enter.
3. בהפעלה הראשונה הסקריפט יוצר קובץ .env מתוך הדוגמה, מתקין את הספריות ומפעיל את המערכת.
   זה יכול לקחת דקה או שתיים.
4. הדפדפן ייפתח אוטומטית בכתובת http://127.0.0.1:8000 עם לוח המחוונים.
   אם לא נפתח, הקלידו את הכתובת בדפדפן בעצמכם.
5. לעצירה: סגרו את החלון השחור, או לחצו בו Ctrl+C.

המערכת סורקת כל דקה. בסבב הראשון היא רק לומדת את רשימת הזוגות, ולכן עסקאות ראשונות
יופיעו רק אחרי שתזוהה קפיצת נפח שעומדת בכל התנאים. ייתכן שיעברו שעות ללא עסקה.
זה תקין: המערכת נכנסת רק כשיש אות.

### שינוי הגדרות
פתחו את הקובץ .env בפנקס רשימות (Notepad) או בכל עורך טקסט. כל שורה מוסברת בעברית.
אחרי שינוי יש להפעיל את המערכת מחדש. הערכים שנקבעו בשלב התכנון:

| הגדרה | ערך | משמעות |
|---|---|---|
| START_BALANCE | 100 | יתרת סימולציה התחלתית בדולר |
| MAX_DAILY_LOSS_PCT | 50 | הפסד יומי מרבי. בחריגה: עצירת חירום |
| MAX_POSITION_PCT | 50 | גודל פוזיציה מרבי מתוך ההון |
| RISK_PER_TRADE_PCT | 2 | סיכון לעסקה בודדת (עד הסטופ-לוס) |
| MAX_OPEN_POSITIONS | 3 | פוזיציות פתוחות בו-זמנית |
| STOP_LOSS_PCT / TAKE_PROFIT_PCT | 3 / 6 | יציאה בהפסד או ברווח |
| TRAILING_START_PCT / TRAILING_STOP_PCT | 3 / 2 | סטופ נגרר: מופעל אחרי עלייה של 3%, נשמר 2% מתחת לשיא, רק עולה. 0 מכבה |

הערה על הערך 50%: מגבלות של 50% הן אגרסיביות מאוד. עם תקרת פוזיציה של 50% נכנסות
לכל היותר שתי פוזיציות במקביל, והפסד יומי של 50% מתיר אובדן מחצית ההון ביום אחד.
לסימולציה זה מקובל. לפני כל מעבר לכסף אמיתי מומלץ לשקול ערכים נמוכים בהרבה.

## רכיבי המערכת

| רכיב | קובץ | תפקיד |
|---|---|---|
| סורק | app/scanner.py | איתור זוגות חדשים ב-AssetPairs וקפיצות נפח לפי נרות של 5 דקות |
| בודק איכות | app/screener.py | סינון לפי סטטוס, נפח, מרווח, מספר עסקאות, גיל זוג ומינימום הזמנה |
| ניהול סיכון | app/risk.py | גודל פוזיציה לפי סיכון, תקרות, וגבול ההפסד היומי |
| מבצע | app/executor.py | מילוי מדומה במחירי ask/bid אמיתיים, עם סליפג' ועמלות |
| יומן | app/journal.py | SQLite: עסקאות ונימוקים, עקומת הון, זוגות מוכרים, אירועים, מצב |
| אסטרטגיה | app/strategy.py | כללי כניסה (מומנטום על קפיצת נפח) ויציאה (סטופ, סטופ נגרר, יעד, זמן) |
| לולאת מסחר | app/bot.py | הסבב המלא, עצירת חירום, שמירת מצב בין הפעלות |
| שרת ולוח | app/main.py, app/static/index.html | FastAPI ולוח מחוונים בעברית |
| לקוח Kraken | app/kraken.py | AssetPairs, Ticker, OHLC מה-API הציבורי |

### על "בודק ההונאות" בזירה מרכזית
ב-Kraken אין חוזים חכמים, ולכן אין משמעות לנזילות נעולה, לריכוז מחזיקים או להרשאות
חוזה. הסיכונים בזירה מרכזית שונים: זוג במצב ביטול בלבד, נזילות דלה, מרווח רחב,
שוק עם מעט עסקאות, וזוג חדש בשעותיו הראשונות. הבודק מסנן בדיוק את אלה, ודוח הבדיקה
המלא נשמר ביומן לכל עסקה. אם בעתיד תעבור המערכת לרשת מבוזרת, רכיב זה הוא היחיד
שיוחלף.

### מגבלות קשיחות ועצירת חירום
- בכל סבב מחושב ההון (מזומן ועוד שווי הפוזיציות במחיר bid). אם ההון יורד אל הגבול
  היומי או מתחתיו, המערכת עוברת לעצירת חירום: כל הפוזיציות נסגרות במחיר השוק
  ולא נפתחות חדשות.
- העצירה נשמרת בבסיס הנתונים. הפעלה מחדש של התוכנה אינה מבטלת אותה.
- החידוש נעשה רק בלחיצה על הכפתור "חדש פעילות אחרי עצירת חירום" בלוח המחוונים,
  ואז מדידת ההפסד היומי מתאפסת להון הנוכחי.
- לפני כל קנייה נבדק שוב שהסכום אינו חורג מתקרת הפוזיציה. חריגה נחשבת תקלה
  לוגית וגוררת עצירת חירום.
- אחרי עשרה כשלי תקשורת רצופים מול Kraken, הסריקה מושהית עד לחיצה על "המשך".
  פוזיציות פתוחות ממשיכות להיות מנוהלות גם בהשהיה.

### סודות
מפתחות API נקראים מקובץ .env בלבד. הקובץ רשום ב-.gitignore ולעולם אינו מועלה
למאגר. בסימולציה השדות נשארים ריקים. המערכת לעולם אינה כותבת את ערכי המפתחות
ליומן או למסך.

## בדיקות
```
python -m pytest
```
הבדיקות רצות ללא רשת, על נתוני דוגמה במבנה המדויק של תשובות Kraken, ובודקות
את הפענוח, את גודל הפוזיציה, את עצירת החירום, את הביצוע המדומה ואת הלולאה המלאה
(כניסה, יעד רווח, סטופ-לוס, פקיעת זמן, שמירת מצב בין הפעלות).

## קבצים שנוצרים בהרצה
- data/trader.db: בסיס הנתונים עם כל העסקאות וההיסטוריה. מחיקתו מאפסת את הסימולציה
  ליתרה ההתחלתית.
- .env: ההגדרות שלכם.

## השלב הבא: מסחר אמיתי
תכנון מפורט של רכיב המסחר האמיתי, ההרשאות הנדרשות למפתח ושלבי המעבר נמצא
בקובץ docs/live-trading-plan.md. זהו מסמך תכנון בלבד ואינו מפעיל דבר.

יתווסף רק לאחר תקופת סימולציה ובהחלטה מפורשת. הממשק Executor כבר מוכן, כך שהחלפת
הסימולציה בביצוע אמיתי אינה דורשת שינוי בשאר הרכיבים. לפני כן יידרשו: מפתחות API
עם הרשאת מסחר בלבד (ללא משיכה), אימות הרשאות, הגבלת סכום כוללת, וטיפול בהזמנות
שמולאו חלקית.
